## Что это такое

`gramsnap` — это self-hosted веб-приложение для экспорта истории Telegram-чатов в JSON. Аналог встроенного «Export chat history» в Telegram Desktop, но с веб-интерфейсом, поддержкой нескольких пользователей и фильтрацией по датам.

Никаких сторонних серверов, никакой базы данных, никаких файлов на диске. Всё работает в одном процессе: авторизация, выборка сообщений, скачивание результата — всё это происходит прямо в браузере и тут же исчезает.

---

## Что делает

1. Авторизуешься через номер телефона → код из Telegram → 2FA-пароль (если включён)
2. Выбираешь нужные чаты в сайдбаре
3. Указываешь диапазон дат
4. Жмёшь «Экспортировать»
5. Файл скачивается в браузер — один JSON или ZIP с несколькими JSONL

На сервере после скачивания **ничего не остаётся**.

От Telegram Desktop отличается тремя вещами:
- Можно выбрать конкретные чаты и точный диапазон дат через веб-интерфейс
- Не нужно регистрировать приложение на `my.telegram.org`
- Один инстанс обслуживает нескольких пользователей одновременно — у каждого своя изолированная сессия

## Форматы вывода

### JSONL — один файл на чат

Каждое сообщение — отдельная строка. При выборе нескольких чатов файлы склеиваются в ZIP.

```jsonl
{"id":12345,"date":"2026-05-07T18:24:11.000Z","fromId":"987654321","fromName":"Алиса","text":"привет","replyToMsgId":null,"forwardedFrom":null,"mediaType":null,"mediaFileName":null,"mediaSize":null}
{"id":12346,"date":"2026-05-07T18:25:00.000Z","fromId":"111222333","fromName":"Боб","text":"ку","replyToMsgId":12345,"forwardedFrom":null,"mediaType":null,"mediaFileName":null,"mediaSize":null}
```

### JSON — один общий файл

Все чаты и сообщения в одном JSON-объекте. Удобно для скриптов и последующей обработки.

> **Медиафайлы не скачиваются.** В записи сохраняются только метаданные: MIME-тип, имя файла и размер.

Поля каждого сообщения:

| Поле | Тип | Описание |
|---|---|---|
| `id` | number | ID сообщения в Telegram |
| `date` | string (ISO 8601) | Дата и время отправки (UTC) |
| `fromId` | string | Числовой ID отправителя |
| `fromName` | string | Имя отправителя на момент сообщения |
| `text` | string \| null | Текст сообщения |
| `replyToMsgId` | number \| null | ID сообщения, на которое это является ответом |
| `forwardedFrom` | string \| null | Источник пересланного сообщения |
| `mediaType` | string \| null | MIME-тип медиафайла |
| `mediaFileName` | string \| null | Оригинальное имя файла |
| `mediaSize` | number \| null | Размер файла в байтах |

## Установка и запуск

```sh
bun install
bun run dev
```

Открыть [http://localhost:5173](http://localhost:5173).

В dev-режиме Vite запускается на порту `5173` и проксирует `/api/*` на Hono, который слушает порт `3001`.

**Требования:** [Bun](https://bun.sh) 1.x. Node.js не нужен.

---

## Продакшн

```sh
bun run build   # клиент → dist/client, сервер → dist/server/index.js
bun run start   # один процесс, порт по умолчанию 3001
```

Открыть [http://localhost:3001](http://localhost:3001). В prod-режиме Hono сам отдаёт собранный фронтенд — отдельный Vite не нужен.

### Работа через HTTP-прокси

gramjs умеет работать через SOCKS, но не через HTTP CONNECT. Сервер сам поднимает локальный мост SOCKS5 ↔ HTTP CONNECT, так что достаточно указать HTTP-прокси:

```sh
# PowerShell
$env:TELEGRAM_HTTP_PROXY="http://127.0.0.1:10809"; bun run start

# bash
TELEGRAM_HTTP_PROXY=http://127.0.0.1:10809 bun run start
```

## Конфигурация

Всего две переменные окружения. Никаких API-ключей, никаких `.env`-секретов.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `3001` | Порт HTTP-сервера |
| `TELEGRAM_HTTP_PROXY` | — | URL HTTP CONNECT прокси. Сервер внутри себя проксирует через него SOCKS5 для gramjs. |

## Что приложение трогает

> [!IMPORTANT]
>
> | | |
> |---|---|
> | Куда ходит | В Telegram через MTProto, как любой другой Telegram-клиент |
> | Диск сервера | Ничего не пишет. Никакой БД, никаких папок `data/` или `exports/` не создаётся. |
> | RAM сервера | Для каждой сессии: список диалогов, миниатюры аватарок, буферы готовых экспортов. Idle-сессии вылетают через 15 минут, экспорты — через 30. |
> | localStorage в браузере | Один ключ `gramsnap.session.v1` — строка-сессия gramjs |
> | Сеть наружу | Только Telegram MTProto, опционально через `TELEGRAM_HTTP_PROXY` |

Используются публичные `api_id` Telegram Desktop (зашиты в код), поэтому регистрироваться на `my.telegram.org` не нужно.

Это **не** сквозное шифрование — сервер читает данные чатов так же, как это делает обычный Telegram Desktop.

Отозвать сессию можно тремя способами:
- Выйти через кнопку в UI
- Очистить site data в браузере
- Убить сессию в Telegram → Настройки → Устройства

## Как это работает

После логина gramjs возвращает `StringSession` клиенту, и тот кладёт её в `localStorage`. Каждый последующий запрос отправляет эту строку обратно в заголовке `X-Gramsnap-Session`. Сервер держит подключённый `TelegramClient` в памяти, ключуя по строке-сессии, и проксирует MTProto от имени пользователя.

Несколько пользователей могут жить в одном процессе — они изолированы своей сессией. Перезапуск сервера никого не выкидывает: при следующем запросе клиенты подключаются обратно из того, что лежит у них в браузере.

## Заметки и ограничения

**Сессии Telegram Desktop переиспользовать нельзя.** Они хранятся в TDLib-формате `tdata`, а это несовместимо с MTProto-сессиями gramjs. Залогиниться придётся один раз через веб-интерфейс. Telegram при этом можно оставить запущенным — это две независимые сессии, конфликта не будет.

**Строка сессии в localStorage — это креденшел.** Тот, кто её прочитает, сможет залогиниться от твоего имени. Относись к ней как к любой установленной копии Telegram-клиента на чужой машине.

**Стек:** Bun, Hono, gramjs, React 18, Vite, Tailwind v3. Без БД, без ORM, без state-management, без UI-библиотеки.
